What it is

Agonas is an open-standard Agent Skill (following the agentskills.io format), also packaged as a Claude Code plugin.

Given a GitHub issue, Agonas parses who asked to work on it, gathers their real GitHub activity and current workload, scores applicants across objective and subjective criteria, presents an explainable scorecard, and assigns the winner only after the maintainer explicitly approves.

Deterministic code enforces fairness rules, anti-monopoly caps, and workload limits; Google Gemma judges only the two subjective elements: the technical quality of the applicant's comment and their domain alignment.

The 3-stage pipeline

Stage 1

Ingest

Reads the issue title, body, labels, and media. Scans comments for claim phrases ("assign me", "I'll take this", "working on this"). Filters out maintainers, collaborators, and bots. Infers difficulty tier (starter, intermediate, advanced).

Stage 2

Score

Queries real candidate telemetry: languages, top repos, lifetime merged PRs, and open issues across GitHub and in this repository. Google Gemma scores comment depth and domain fit. Deterministic code enforces the rest.

Stage 3

Decide

Outputs an explainable Markdown scorecard, Rich terminal table, and HTML report. Assigns the winner only when the maintainer passes --confirm. Without write access, outputs an advisory snippet instead.

Why it matters

Manual triage is slow, biased toward the fastest bot, and vulnerable to hoarding.

Generic claim spam

Maintainers receive dozens of "assign me pls" comments with no implementation plan. Reviewing applicant profiles by hand drains maintainer energy.

Agonas fix: Google Gemma assesses technical depth, file references, and reproduction code. Generic claims score 0–2 points.

Issue hoarding & ghosting

Serial claimers collect open issues across multiple repositories simultaneously, then abandon them after blocking progress.

Agonas fix: Deterministic GitHub Search queries check global open assigned issues. Candidates with 5+ open tickets receive 0 points and a "High ghosting risk" flag.

Repository monopolies

A single active contributor can monopolize ticket queues, preventing other community members from contributing.

Agonas fix: Strict anti-monopoly rule: candidates with 3 or more open assigned issues in the same repo have their composite score hard-capped at 4.0.

Newcomer exclusion

Experienced contributors often claim entry-level "good first issue" tickets in seconds, crowding out new contributors.

Agonas fix: On starter issues, first-timers (≤2 merged PRs) receive a +2.0 boost; contributors with >10 merged PRs receive a -2.0 adjustment.

How scoring works

Every candidate receives a composite score from 0.0 to 10.0 based on explicit, published rules.

Pillar Weight Scored by Criteria & Thresholds
Comment quality and intent 30% Gemma Evaluates technical substance, reproduction code, or specific fix plan. Generic claims score 0–2; detailed proposals score 8–10.
Global open-issue burden (anti-hoarding) 20% Code 0 open issues → 10 pts; 1–2 open → 7 pts; 3–4 open → 3 pts; 5+ open → 0 pts + "High ghosting risk" flag.
Same-repo monopoly (anti-monopoly) 20% Code 0 active issues → 10 pts; 1 active → 6 pts; 2 active → 2 pts; 3+ active → 0 pts and total score capped at 4.0 max.
Technical and domain alignment 15% Gemma Matches language, framework, and repo history. Adjacent ecosystems get credit (e.g. JavaScript proficiency applied to TypeScript).
First-timer boost Adjustment Code Applied on starter tier issues: ≤2 lifetime merged PRs → +2.0 bonus; >10 lifetime merged PRs → -2.0 penalty.

Core principle: Gemma judges words; code enforces fairness. Subjective prose evaluation is strictly bounded by deterministic checks so model output cannot bypass workload limits or monopoly caps.

Set up

Get Agonas running in Claude Code or as a standalone Agent Skill in three steps.

1

Requirements

  • Python: Version 3.10 or higher.
  • GitHub Token: A classic Personal Access Token with repo scope, or a fine-grained PAT with Issues read/write. Assigning requires triage or write access to the repository.
  • Gemini API Key: A key from Google AI Studio for Gemma reasoning.
2

Install

claude plugin marketplace add Rehodra/Agonas
claude plugin install agonas@agonas

Run the marketplace command once in a terminal: 

claude plugin marketplace add Rehodra/Agonas

Then inside the Claude desktop app (Code tab, local session), navigate to: + → Plugins → Add plugin → Agonas.

3

One-time setup

Install Python dependencies inside the plugin folder and save your API keys to ~/.agonas/.env.

pip install -r requirements.txt     # inside the plugin folder (`claude plugin details agonas` shows where)
mkdir -p ~/.agonas && printf 'GITHUB_TOKEN=your_github_token\nGEMINI_API_KEY=your_gemini_key\n' > ~/.agonas/.env
pip install -r requirements.txt     # inside the plugin folder (`claude plugin details agonas` shows where)
New-Item -ItemType Directory -Force -Path "$HOME\.agonas"
@"
GITHUB_TOKEN=your_github_token
GEMINI_API_KEY=your_gemini_key
"@ | Out-File -FilePath "$HOME\.agonas\.env" -Encoding utf8

Get your tokens

  • GitHub Personal Access Tokens: Classic token requires repo scope. Fine-grained token requires Repository permissions → Issues: Read and write.
  • Google AI Studio API Keys: Create a free API key for Gemma inference via the Google GenAI SDK.

"Assign issue #4 to the relevant person"

/agonas:agonas

What happens next

  1. Execution: Claude runs Agonas scripts in sequence (fetch_issue_context.py, fetch_candidate_metrics.py, evaluate_gemma.py).
  2. Presentation: Claude renders the Markdown scorecard with candidate rankings, scores (0–10), justifications, and risk flags.
  3. Human approval gate: Claude halts and requests your approval before executing any mutation. Agonas will never assign without your explicit confirmation.
  4. Advisory fallback: If your GitHub token lacks write access to the target repository, Agonas prints a formatted advisory Markdown comment that you can copy and paste into the issue discussion.

Safety and trust

Engineered with defensive guardrails for open-source repositories.

Human-in-the-loop by default

Agonas never modifies GitHub state automatically. The assignment script strictly requires an explicit --confirm flag passed by the human maintainer.

Keys stay on your machine

Your GITHUB_TOKEN and GEMINI_API_KEY reside in your local ~/.agonas/.env. They are never sent to third-party telemetry or remote logging services.

Untrusted input boundaries

Issue descriptions and applicant comments are treated as untrusted text. System prompts isolate user prose to prevent prompt injections from influencing scoring logic.

Automated maintainer filtering

Existing repository maintainers, collaborators, and bots (like dependabot or github-actions) are automatically detected and excluded from the applicant pool.

Automatic model fallback

Agonas targets gemma-4-31b-it by default for maximum reasoning capability, gracefully falling back to gemma-4-26b-a4b-it if the primary endpoint is overloaded.

Zero write mutation risk

If run with a read-only token or on external repositories, write operations fail safely and print an advisory Markdown snippet for manual use.

Frequently asked questions

Does it work without a Gemini key?

Yes. Agonas includes an offline heuristic evaluation mode (invoked via --heuristic). This mode relies strictly on comment length, regex heuristics, and repository metadata without NLP inference. It is clearly labeled as lower-quality compared to the Gemma-backed pipeline.

Can it assign on repositories I do not own?

Assigning an issue on GitHub requires triage or write permissions on the target repository. If your GITHUB_TOKEN lacks write access, Agonas will not fail or crash; it automatically outputs an advisory snippet summarizing the evaluation that you can paste into the issue discussion for maintainers to review.

What counts as an applicant claim?

Agonas checks issue comments for common claim patterns such as "assign me", "I'll take this", "can I work on this", "working on this", "claim", or technical proposals asserting intent. Comments from bots and established repository maintainers are filtered out automatically.

Does Agonas replace open-source maintainers?

No. Agonas is a recommendation assistant designed to save maintainers time. It aggregates telemetry, surfaces risk flags, and suggests the highest-ranked applicant according to fair published criteria. The maintainer always retains final authority and must approve the assignment.

Which AI model does Agonas use?

Agonas uses Google Gemma open-weight models accessed via the official Google GenAI SDK. The default reasoning model is gemma-4-31b-it, with an automatic fallback to gemma-4-26b-a4b-it if the primary endpoint experiences high load or rate limits. You can also customize the model using the GEMMA_MODEL environment variable.
